# Connections, access and secrets checklist

Verified handover date: 10 November 2026 (Asia/Singapore). [Start here](00-START-HERE.md) · [Feature evidence](02-FEATURE-STATUS-MATRIX.md) · [Validation](17-HANDOVER-VALIDATION.md)

## Restore access on the new account

| Surface | How to restore | Verify | Never transfer |
|---|---|---|---|
| Public GitHub source | Clone URL or verified local bundle | remote URL, HEAD, git fsck, branch/CI | PAT/cookie from old session |
| GitHub write/plugin | Connect GitHub in the new Codex/ChatGPT settings as the authorized repository owner; grant only needed repo scope | read repo metadata first, inspect tool availability before push | stored connector credentials or unrelated repositories |
| Supabase plugin | Connect through new account's own OAuth/owner login; select existing Minecraft project | list migrations + read-only aggregate/RLS/advisor checks | service-role/API secret, database password |
| Google OAuth administration | Owner signs into existing dedicated Google Cloud project; inspect basic scopes/origin/callback/audience | callback matches existing Supabase project and Pages origin | client secret, account cookies/password |
| Existing website Owner | Normal Google login with the approved account; membership remains in DB | profile/approved capabilities on the correct server | database role impersonation as a substitute for login |
| Browser tools | Enable/authorize available browser extension/session in new environment | inspect existing relevant tab; read-only first | export of browser sessions/cookies |
| Mac filesystem | Open actual local folder in Codex; grant only that folder and private facts needed | realpath/modes, local README/index, no unexpected sync/root | automatic full private-directory upload |
| Ubuntu | Local terminal or a separately approved trusted access method; no assumed SSH | read-only inventory and actual mapping | SSH private key or public SSH exposure |

Connector permissions and ChatGPT memory do not transfer between accounts. Connected tool presence alone is not proof of valid authorization; inspect actual read-only results. Do not disconnect/delete the previous connectors as part of handover.

## Secret inventory — metadata only

| Item | Purpose/storage | Exists? | Provision/rotation/recovery |
|---|---|---|---|
| Supabase publishable key | Intentionally public client routing in src/client.ts and example | Yes, public | Does not grant authority; retain RLS; not an exception for service-role keys |
| Google OAuth client secret | Supabase provider secret store; Google project manages client metadata | Historically configured; value not read | Owner administratively rotates client + updates Supabase privately; retest PKCE/callback |
| Owner Google authentication | Owner's Google/password manager | Account exists; secret not read | Normal provider recovery/rotation, not chat export |
| Dedicated agent password | Private Ubuntu env/password manager after approved provisioning | Not provisioned at handover | Confirm service Auth identity, bind exact server, rotate/revoke sessions and update root-managed env privately |
| Crafty stats/control token | Private Ubuntu env or per-server config after approval | No dashboard token provisioned | Create narrow stats-only identity for A; separate reviewed B rights; revoke/rotate in Crafty |
| Trusted local Crafty CA | Verified existing local certificate; proposed private config path | Not inspected/copied | Validate provenance/fingerprint/SAN from controlled local files; never disable TLS |
| Archive master key | Proposed owner-only private Ubuntu key | Not generated by this project yet | Installer only after approval; encrypted independent recovery copy; preserve old key for old ciphertext |
| Per-server bridge secret | Only exact server socket/key directories | Not generated/deployed | Stage C separate key from archive key; reviewed isolation/group/mounts; rotate and test privately |
| SSH keys / DB password / service role | Not needed for browser frontend or normal scoped agent | Not collected, existence unknown | Keep existing password manager; use minimum necessary authorized channel if a later task truly needs one |

Local private notes contain configuration metadata/templates and known/unknown provenance, not secret values. No encrypted secret backup was necessary or authorized in this handover. If later required, request specific approval and a secure local encryption/key-recovery design first. OS modes do not protect against a compromised owner account or undisclosed sync software.
